# Phase 1.5 Frontend — Auth, DB Criteria, Criteria Editor, Stair-Tower Loader

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the frontend half of Phase 1.5: session-gated app shell, login/setup page, per-user criteria panel fed by the API, an animated criteria editor dialog, and the pure-CSS stair-tower loader replacing the Three.js run visual.

**Architecture:** React 19 + Vite. `AuthProvider` owns session state (`GET /auth/me`), `RequireAuth` guards every route except `/login`. `api/client.ts` gains `put`, 204 handling, and a `auth:unauthorized` window event on 401 (login/setup exempt) that clears auth state and triggers redirect. Criteria live in the backend DB per user; the panel renders badges from `GET /screen/criteria` + `GET /screen/ratios`, and `CriteriaDialog` edits them via `PUT /screen/criteria`. `StairTowerLoader` is pure CSS + one hook, replacing `RunVisual`.

**Tech Stack:** React 19, TypeScript, Vite 8, vitest 5 + jsdom + Testing Library, Chakra UI v3 (`Dialog`, `Combobox`, `Switch`, `Field`, `Textarea`, `Button` spinner slot), Tailwind v4, `motion` v13 (`motion/react`), lucide-react.

**Spec:** `docs/superpowers/specs/2026-09-26-phase-1.5-authorization-db-screener-design.md` — section "Frontend component specs" is the binding contract; backend endpoints below are as pinned by the spec's API contract.

## Global Constraints

- No new frontend dependency (spec constraint 45). Loader = pure CSS + existing Chakra.
- `frontend/DESIGN.md` is binding: semantic tokens only, lucide icons only, `prefers-reduced-motion` honored, no continuous animation inside data areas (the loader is the single sanctioned exception).
- Frontend scope only: do not touch `backend/`, root `PLAN.md`, or `plan/` (parallel backend agent works those).
- Remove every reference to `screening.yaml`, `/screen/config`, `config_yaml`, and `RunVisual` from `frontend/` (spec grep gate).
- All tests offline; all network mocked. `npm run test` and `npm run build` green before every commit.
- Update `frontend/FRONTEND.md` and `frontend/DESIGN.md` in the same branch (spec constraints section).
- Backend response shapes (pinned by spec API contract):
  - `GET /auth/state` → `{users_exist: boolean, user: AuthUser | null}`
  - `POST /auth/setup {username, password}` → 201 `AuthUser`; 409 when a user exists; 422 validation
  - `POST /auth/login {username, password}` → 200 `AuthUser`; 401 generic detail
  - `POST /auth/logout` → 204
  - `GET /auth/me` → `AuthUser`; 401 `Not authenticated`
  - `GET /screen/ratios` → `RatioSpec[]`
  - `GET /screen/criteria` → `UserCriteria`
  - `PUT /screen/criteria {criteria, thesis?}` → saved `UserCriteria`; 422 with `detail`
  - `POST /screen/run` → `ScreenRunResult` (unchanged); `GET /screen/latest` → `LatestScreen` (unchanged)

## Review Focus (tests pin these)

1. Session expires mid-run: `POST /screen/run` succeeds, then `/screen/latest` returns 401 → no crash, `auth:unauthorized` clears user, redirect to `/login` happens once (no redirect loop).
2. Two-tab setup race: setup returns 409 → message shown, page switches to the login card, no crash, username preserved.
3. Dialog open with `GET /screen/criteria` failing → inline error + working Retry; dialog is never blank.
4. Double-submit while a request is pending (login/save) → button `disabled` + tower loader, exactly one network call.
5. Non-numeric / empty row value or zero enabled criteria on save → inline row error, no `PUT` fired.
6. 401 on login/setup must NOT dispatch `auth:unauthorized` (otherwise the local inline error is swallowed by a redirect).

`request()`:

```ts
const AUTH_ENTRY_PATHS = new Set(['/auth/login', '/auth/setup'])

async function request<T>(path: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`${BASE}${path}`, {
    headers: { 'Content-Type': 'application/json' },
    ...init,
  })
  if (!res.ok) {
    const detail = await errorDetail(res)
    if (res.status === 401 && !AUTH_ENTRY_PATHS.has(path)) {
      window.dispatchEvent(new Event(AUTH_UNAUTHORIZED_EVENT))
    }
    throw new ApiError(res.status, detail)
  }
  if (res.status === 204) return undefined as T
  return res.json() as Promise<T>
}
```

```tsx
          {loadError ? <Stack gap={3}><Text role="alert" color="fg.error">{loadError}</Text><Button size="sm" onClick={load}>Retry</Button></Stack> : rows + thesis + combobox}

        <Dialog.Footer><Button variant="outline" onClick={() => onOpenChange(false)}>Cancel</Button><Button colorPalette="emerald" loading={saving} spinner={<StairTowerLoader size={20} label="Saving…" />} onClick={save} disabled={saving}>Save</Button></Dialog.Footer>

    </Dialog.Positioner>
  </Portal>
</Dialog.Root>
```
