# Phase 1.6b — Nifty 500 Universe Search + Richer Stock Detail (design)

**Date:** 2026-09-27
**Status:** Approved design, pending implementation
**Branch:** `phase-1.6` (continuation of Phase 1.6)
**Phase plan:** `plan/phase-1.6b-universe-search/{backend,frontend,database}.md`

## 1. Goal

Let a user search/browse the whole Nifty 500 universe and open any stock, not only
screen survivors:

1. a **Stocks page** (`/stocks`) — searchable, filterable, sortable table of all
   ~500 stocks with key ratios, stored-data date and *that user's* screen verdict;
2. **shared fundamentals for the whole universe** — the screen run refreshes every
   stock whose stored snapshot is not from today, so one run fills the common DB
   for all users;
3. a **richer stock detail page** — description/industry, market cap, balance facts
   ("what it has"), main ratios, performance facts ("what it's done"), screen data,
   and all remaining catalog ratios.

Daily prices/candles stay live-only (yfinance + memory cache); they are never stored.

## 2. Locked decisions

| Decision | Choice |
|---|---|
| Screen-run fetch scope | Refresh **every universe symbol** with no `ok` row for today (not only gate survivors); same-day reruns cost 0 network |
| Shortlist | Unchanged: staged criteria, top-10 clamp, per-user |
| Verdict on the list | Computed per request from stored snapshot + caller's criteria; never persisted |
| Profile store | New `company_profiles` table (`symbol` PK, slow-moving fields); `create_all` adds it — no migration rig exists |
| Raw payload | `raw_json` stores a **whitelist** (catalog raw fields + detail facts), not the full `.info` dump |
| Prices | Never written to the DB (Phase 3 owns `prices`); `/stocks` and `/stock/*` read only |
| Search | Client-side over one `GET /stocks` payload (~500 rows); no server-side q/sort |
| Detail sections | Server-composed `main_ratios` / `has` / `done` / `other_groups` + `profile`; frontend renders blindly |

## 3. Backend

### 3.1 New table `company_profiles`

`symbol` PK, `industry`, `sector`, `description` (Text), `website`, `employees`
(Integer), `hq` (Text), `updated_at` (String). Written on every successful
fundamentals fetch alongside the dated `fundamentals` row (upsert via `merge`).

### 3.2 New package pieces

- `app/stock/digest.py` — pure section builder:
  - `FactSpec(key, label, unit, source: "derived"|"raw", yf_field=None, scale=1.0)`
  - `MAIN_FACTS` = pe, pb, roe, roce, debt_to_equity, dividendYield
  - `BALANCE_FACTS` ("has") = market_cap, totalRevenue, ebitda, netIncomeToCommon,
    operatingCashflow, freeCashflow, totalCash, totalDebt, bookValue, currentRatio,
    quickRatio — currency facts scaled to ₹ cr (`1e-7`)
  - `PERFORMANCE_FACTS` ("done") = revenueGrowth, earningsGrowth,
    earningsQuarterlyGrowth, grossMargins, operatingMargins, ebitdaMargins,
    profitMargins, returnOnAssets, payoutRatio, fiveYearAvgDividendYield
  - `build_sections(row) -> {"main_ratios", "has", "done", "other_groups"}` —
    metrics `{key, label, unit, value}`, `None`/NaN skipped; `other_groups` is the
    catalog grouped like `build_report`, minus every key already used above.
- `app/stock/store.py` — storage policy helpers:
  - `RAW_FIELDS: frozenset[str]` = catalog raw `yf_field`s ∪ digest fact `yf_field`s
  - `trim_raw(info) -> dict` — whitelist, drops `None`
  - `upsert_profile(session, symbol, info, updated_at)` — no commit (caller owns tx)
  - `read_profile(session, symbol) -> dict` — all-`None` when absent
- `app/stock/universe.py` — `list_universe(session_factory, provider, user_id)`:
  seeds `stocks` from `provider.list_stocks()` when the table is empty (no
  fundamentals fetch), loads every stock + newest `ok` row, counts per-criterion
  passes with the caller's criteria, emits rows sorted by symbol.

### 3.3 Changes to existing modules

- `screener/engine.py`: `_passes` → public `passes(value, limit, direction)`.
- `screener/service.py`: `_latest_ok_fundamentals` → public
  `latest_ok_fundamentals`; stage 2 builds `refresh_symbols` from *all* symbols
  without a today `ok` row; final candidates = fresh-or-stored for every symbol;
  writes use `trim_raw` + `upsert_profile`.
- `stock/report.py`: extract `build_catalog_groups(row, skip_keys=frozenset())`;
  `build_report` delegates to it (behavior unchanged).
- `stock/service.py`: `_store_ok` trims raw + upserts the profile; detail payload
  gains `profile`, `main_ratios`, `has`, `done`, `other_groups`.
- `api/stocks.py` — thin router `GET /stocks` (auth dependency), mounted
  `prefix="/stocks"`; `main.py` includes it; `conftest.py` patches its
  `SessionLocal`/`init_db`.

### 3.4 API contracts

`GET /stocks`:

```json
{
  "as_of": "2026-09-26",
  "total": 500,
  "rows": [
    {"symbol": "RELIANCE", "name": "Reliance Industries Ltd", "sector": "Oil & Gas",
     "market_cap": 1900000.0, "pe": 24.1, "pb": 2.1, "roe": 8.9, "roce": 9.4,
     "debt_to_equity": 0.42, "data_date": "2026-09-26",
     "passes": 5, "enabled": 5, "verdict": "pass"}
  ]
}
```

`verdict` ∈ `"pass" | "fail" | "no_data"` (no stored `ok` snapshot);
`as_of` = newest `data_date` across rows (null when empty).

`GET /stock/{symbol}` response adds (existing keys unchanged):

```json
{
  "profile": {"description": "…", "industry": "Oil & Gas", "sector": "Energy",
               "website": "https://…", "employees": 350000, "hq": "Mumbai, Maharashtra, India"},
  "main_ratios": [{"key": "pe", "label": "P/E", "unit": "×", "value": 24.1}],
  "has":  [{"key": "totalRevenue", "label": "Revenue", "unit": "₹ cr", "value": 930000.0}],
  "done": [{"key": "revenueGrowth", "label": "Revenue Growth", "unit": "%", "value": 11.2}],
  "other_groups": [{"category": "Valuation", "metrics": [{"key": "forwardPE", "label": "Forward P/E", "unit": "×", "value": 21.0}]}]
}
```

`profile` keys are always present (`null` when unknown); metric arrays skip
missing values. `POST /stock/{symbol}/refresh` returns the same shape.

## 4. Database

- New table `company_profiles` — one row per symbol; `merge` upsert; not dated.
- `fundamentals` schema unchanged; `raw_json` now whitelist-only (bounded rows).
- Screen run: one `ok` (or `failed`) row per symbol per day; failed rule unchanged
  (`failed` only when no same-day `ok`).
- `prices` stays empty until Phase 3; no candle writes anywhere.

## 5. Frontend

- `pages/Stocks.tsx` (`/stocks`) + `components/StocksTable.tsx`; `GlassNav` gains a
  "Stocks" link. Search by symbol/name, sector filter, verdict filter; sortable
  table (symbol link, name, sector, mkt cap, PE, PB, ROE%, ROCE%, D/E, screen
  badge, data date); skeleton/empty/error+retry states.
- `pages/StockDetail.tsx` section order:
  1. header (name, sector, market cap, data-as-of, Refresh, run chips) — unchanged
  2. Candle Ridge strip — unchanged
  3. screen data (`StockReportCard`)
  4. description card: description, industry, sector, website, employees, HQ
  5. "What it has" tiles (`has`)
  6. main fundamental ratios (`main_ratios`)
  7. "What it's done" tiles (`done`)
  8. other ratios (`other_groups`, catalog-group layout like today's grid)
  9. price chart card — unchanged
- `api/types.ts` gains `StockListRow`, `StockListResponse`, `CompanyProfile`,
  `StockFact`, and the new `StockDetail` keys.

## 6. Error handling

- Per-stock isolation unchanged: one failed fetch never kills a screen run; the
  failed-row rule protects same-day `ok` snapshots.
- `/stocks` with an empty DB seeds the universe lazily; upstream seeding errors
  (`httpx`) ride the global handler → 502, like the screen run.
- Missing profile / missing metric fields render as absent tiles, never blank
  cards or crashes; chart errors keep their existing Retry.
- 401 rides the global redirect.

## 8. Acceptance

- Any of the ~500 symbols is findable from `/stocks` and openable at `/stock/{symbol}`.
- One screen run stores today's `ok` row for every reachable universe stock; a

  user criteria.
- Detail page shows screen data directly under the header, then description,
  "has", main ratios, "done", other ratios, chart.

- Backend suite, frontend suite and `npm run build` green; docs + knowledge graph
