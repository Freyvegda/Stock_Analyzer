# Phase 1.7 — Saved screens, inline criteria editor, navbar search (Design)

**Date:** 2026-09-29 · **Status:** approved by owner (2026-09-29 conversation)

**Plans:** `plan/phase-1.7/database.md`, `plan/phase-1.7/backend.md`, `plan/phase-1.7/frontend.md`.

## Why

1. **Inline criteria editor** — `/fundamentals/criteria` opens a dialog to edit ratios. Owner
   wants no subwindow: the full criteria table renders inline, the accordion expands itself,
   ratios are selected/edited through expandable category sub-accordions, then Run Screen.
2. **Multiple saved screens** — today there is exactly one criteria row per user
   (`user_criteria`). Owner wants many named screening criteria per user, stored in the DB,
   pickable ("active screen"), each runnable.
3. **Bigger navbar search** — today a small icon that expands on click. Owner wants a bigger,
   always-visible 3D-glass search bar in the navbar for stock search.

## Owner decisions (Q&A, 2026-09-29)

- **Active screen is the single criteria source:** exactly one saved screen per user is
  active; it drives the Run action, `/stocks` verdicts, and the stock-detail report. Selection
  is persisted server-side so it survives reloads and applies to the whole account.
- **Editor shape:** criteria page shows a screen selector (saved screens + inline New) above
  the full criteria table for the active screen. Ratios are grouped by catalog category; each
  category is a collapsible sub-accordion; rows carry on/off switch + threshold input. Edit
  Criteria expands/scrolls to this editor. No dialogs anywhere in this flow.
- **Per-screen results:** `POST /screen/run` executes the active screen; Top 10 Results shows
  the latest run **of the active screen**; switching the active screen switches the Top 10
  view. `screen_runs` gains `set_id`.
- **Navbar search:** permanently visible glass input (~18–20rem) on desktop; collapses to the
  current icon + expand on small screens; Ctrl/Cmd+K focuses it from anywhere; results panel
  stays as-is (3D perspective entrance, sheen, verdict chips, keyboard navigation).

## Data model (delta)

```sql
screening_sets(
  id            INTEGER PK AUTOINCREMENT,
  user_id       INTEGER NOT NULL FK -> users.id  (indexed),
  name          TEXT NOT NULL,                   -- 1..60 chars, trimmed, unique per user (case-insensitive, service-enforced)
  criteria_json TEXT NOT NULL,                   -- [{key, enabled, value}] same shape as before
  thesis        TEXT NULL,                       -- <= 500 chars, per screen
  shortlist_size INTEGER NOT NULL DEFAULT 10,    -- server-owned
  is_active     INTEGER NOT NULL DEFAULT 0,      -- exactly one active per user, service-enforced
  updated_at    TEXT NOT NULL
)
screen_runs + set_id INTEGER NULL FK -> screening_sets.id (indexed)
```

- `user_criteria` is retired. Dev DB reset (delete `data/stockanalyzer.db`) is the migration,
  matching repo rule "adding a table/column = delete dev DB"; re-run `/auth/setup` after.
- First read of `/screen/sets` for a user with no sets seeds `"Default"` from
  `DEFAULT_CRITERIA`, active.
- Deleting a screen keeps its runs (audit); their `set_id` is nulled. The last remaining
  screen cannot be deleted (400). Deleting the active screen promotes the most recently
  updated remaining one.

## API

| Method | Path | Notes |
|---|---|---|
| GET | `/screen/sets` | list; each item `{id, name, criteria, thesis, shortlist_size, is_active, updated_at}` |
| POST | `/screen/sets` | `{name, criteria?, thesis?}`; criteria omitted → copy active screen's (or defaults); created screen becomes active; 201 |
| PUT | `/screen/sets/{id}` | `{name?, criteria?, thesis?}` — at least one field; 422 on bad payload, 404 unknown id |
| DELETE | `/screen/sets/{id}` | 204; 400 when it is the last screen |
| POST | `/screen/sets/{id}/activate` | single-active switch in one transaction; returns the set |
| POST | `/screen/run` | runs the active screen; `screen_runs` stores `set_id` + criteria snapshot |
| GET | `/screen/latest` | latest run of the active screen; 404 when that screen has no run yet |
| GET | `/screen/ratios` | unchanged |

Retired: `GET/PUT /screen/criteria`. Internal consumers (`/stocks` verdicts,
`/stock/{symbol}` report) keep their payloads but read the active set's criteria through
`service.get_criteria(session_factory, user_id)` (now active-set-backed).

Validation reuses `CriterionItem` / `criteria_from_json`: known keys, no duplicates, at least
one enabled, finite values, criteria length 1–50, thesis ≤ 500, name 1–60; client-sent
`shortlist_size` → 422 (`extra="forbid"`).

## Frontend

- `FundamentalsLayout` keeps owning shared run state and gains sets state: `sets`,
  `activeSet`, `setsError`, actions `activateSet(id)`, `createSet(name)`,
  `updateSet(id, patch)`, `deleteSet(id)`. `activateSet` refetches `/screen/latest` so Top 10
  follows the screen. `runScreen` saves a dirty editor draft first.
- New `ScreenSetPicker` — glass selector (name + criteria count, active marked) with inline
  New / Rename / Delete (two-step confirm). No dialogs.
- Repurposed `CriteriaPanel` — active screen name + criteria badges + Edit Criteria button.
- New `CriteriaEditor` — outer accordion collapsed by default (Edit Criteria expands it),
  category sub-accordions all expanded when opened, per-category "Add criterion" combobox,
  switch + threshold rows with remove, thesis textarea, Save. Dirty tracking; switching
  screens while dirty shows an inline `Save & switch / Discard & switch` bar (no dialog).
- `CriteriaDialog.tsx` + its test are deleted. `UserCriteria` type is replaced by
  `ScreeningSet`.
- `NavSearch` — always-visible `.glass-field` input ≥ md (desktop), current icon + expand
  below md; Ctrl/Cmd+K focuses/opens; results panel unchanged; one `GET /stocks` fetch per
  shell mount stays.
- Top 10 copy for an empty screen: "No run yet for this screen." (with the link back).

## Addendum: criterion bookmarks (2026-09-29, owner-requested during phase build)

**Feature:** each criterion row in the criteria editor can be bookmarked (pinned). One
bookmark = one criterion.

- **Storage:** `criteria_json` items gain an optional `bookmarked: bool` (default `false`) —
  no schema change; old payloads stay valid; the engine ignores the flag.
- **2D design:** every row gets a ribbon toggle (`Bookmark` / `Remove bookmark`, lucide,
  filled when active); bookmarked rows pin to the top of their category keeping relative
  order; an "Bookmarked only" filter chip (`aria-pressed`) shows just those rows and hides
  empty categories (category counts keep counting the full set); the read-only badge list
  marks bookmarked badges with a small ribbon; dirty tracking includes the flag, so Save/Run
  persist it.
- **3D design:** `components/three/RibbonRail.tsx` — one shared lazy three.js canvas at the
  top of the editor: a thin glass rail holding one low-poly sakura ribbon per bookmarked
  criterion (label on the ribbon). Bookmarking slides a ribbon in, unbookmarking withdraws
  it (one-shot animation, no loop); clicking a ribbon calls `onSelect(key)` to highlight/open
  that row. WebGL-gated with CSS fallback absent, static under reduced motion, hidden below
  `md`, rendered only while the editor is open and at least one bookmark exists.
  `DESIGN.md` loop whitelist stays unchanged (one-shot only).
- **Scope:** extends Phase 1.7, implemented on the same branch before the final review.

## Non-goals

`shortlist_size`, migrating old `user_criteria` data (dev reset instead), worktrees.
